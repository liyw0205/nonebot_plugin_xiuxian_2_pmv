# ADR-0001 运行时边界与渐进迁移

日期：2026-09-12  
状态：已接受

## 背景

旧插件由大量包导入副作用注册玩法，数据库连接、消息发送和 Web 路由分散在业务模块中。一次性搬迁会影响现有玩家数据和命令兼容性。

## 选项

1. 一次性重写全部玩法。
2. 保留旧包作为兼容层，先建立 `core`、`bootstrap`、`infrastructure` 和 manifest 边界，再逐个迁移垂直切片。

## 决策

采用选项 2。短期保留多个 SQLite 文件，由 `DatabaseCatalog` 声明所有权；新资产动作必须使用 operation ledger 和 outbox。前端继续使用 Flask/Jinja，新增 API 使用 `/api/v1`。

## 代价与风险

迁移期间会同时存在旧入口和新入口，需要记录兼容命中并在完整发布周期后删除 shim。跨 SQLite 文件不能伪装成原子事务，失败必须进入对账。

## 迁移和回滚

新切片可通过移除 manifest 注册关闭；数据库恢复依赖备份和 `schema_migrations` 校验。旧模块保持可导入，直到日志确认无命中。
